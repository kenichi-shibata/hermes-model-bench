The port accepts connections but the app never responds — the service is hung/blocked at the application layer, not a network problem.

- `dns_ok: true` → hostname resolves
- `tcp_connect_ok: true` → something is listening and accepting on the port
- `app_health_check: "timeout"` → the HTTP/app layer never replies

So a listener is bound (maybe a load balancer/proxy or a stuck process), but the backend health endpoint times out. Check for an overloaded/hung app process, a dead worker behind a proxy, or a health-check path the server never handles (e.g. wrong path, or it blocks waiting on a dependency like DB).
