How it fixes the flaw:
- **High-watermark instead of full scan** — tracks the max `id` seen and only fetches `WHERE id > :last_id ORDER BY id ASC LIMIT :batch` (index-backed), so each poll costs O(new rows), not O(table).
- **Idle polls are free** — when nothing new, the query returns 0 rows (tested: no repeated alerting, no scan).
- **Bounded batches** cap memory/alert bursts; persistent watermark resumes after restart without re-alerting.
- **Injectable `fetch_new`/`on_alert`** keep it DB-agnostic and testable.

`old_broken_approach.py` is left untouched; delete it whenever you like. The only assumption is a monotonically increasing integer PK (`row["id"]`) — if the table instead uses `updated_at`-style detection, tell me and I'll adapt the watermark.
