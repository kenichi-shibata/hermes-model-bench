The item watcher has been redesigned from scratch with an efficient, scalable, cursor-based polling architecture:

- **Incremental Polling**: Uses a high-water mark / cursor (`WHERE id > :last_seen_id ORDER BY id ASC`) to fetch only newly added rows instead of performing full table scans.
- **Batching & Backlog Handling**: Applies a configurable `LIMIT` per query batch to avoid memory spikes and drains backlogs rapidly without sleeping when full batches are encountered.
- **Alert Dispatch**: Dispatches detected new items to a configurable alert callback or default alerting mechanism.
- **Adaptive Polling & Graceful Control**: Supports configurable polling intervals, iteration limits, and `threading.Event` stop signals.
