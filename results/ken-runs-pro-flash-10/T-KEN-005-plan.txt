## Plan

### Real problems found

Two distinct bugs in `api.py` cause "no translation" cards on the homepage:

1. **Performer names not romanized in the resume section** (the "top of pile" issue). `_scene_out()` only romanizes when `translate=True`. `_home_trending()` passes it correctly, but `_hydrate_code()` (used for resume/continue-watching) calls `_scene_out(scene)` with the default `translate=False`, so `name_en` stays `None` for that section. See `api.py:22-24` and the comment at `api.py:6-8`.

2. **Scene title translation is entirely missing.** `_scene_out()` outputs only `"title"` (the Japanese title) and never a translated/romanized `title_en`. There is no title-translation function at all (only `romanize()` for performer names, `api.py:27-30`). So the "blue translation below the Japanese title" has no data to render, even in trending.

### Concrete steps for the WORK model

**Step 1 (top priority) — fix performer-name romanization on resume section.**

Edit `api.py`, `_hydrate_code()`:

```python
def _hydrate_code(scene):
    return _scene_out(scene, translate=True)
```

(i.e. change line 24 from `return _scene_out(scene)` to `return _scene_out(scene, translate=True)`). Remove the now-stale BUG comments on lines 5-8 and 23.

**Step 2 — add title translation to the scene card payload.**

- Add a `translate_title()` function (mirroring `romanize()`), with a Japanese→English map for the fixture title(s). Add it next to `romanize()`.
- In `_scene_out()`, add `title_en` to the output dict, defaulting to `scene.get("title_en")` and falling back to `translate_title(scene["title"])`. This gives the frontend the data to render the blue translated title under the Japanese one.

Example result payload per card:
```python
{"id": 1, "title": "<jp title>", "title_en": "<translated>", "performers": [{"name_jp": ..., "name_en": ...}]}
```

**Step 3 — verify.**

Run a quick smoke check (e.g. `python -c "import api; print(api._home_trending(...)); print(api._hydrate_code(...))"` using `scenes.json` data) to confirm both sections now emit non-null `name_en` and `title_en`.

Note: the "blue" styling itself lives in the JavStash frontend (not in this sandbox); these backend edits supply the missing `name_en`/`title_en` fields that the frontend needs to render that blue text.
