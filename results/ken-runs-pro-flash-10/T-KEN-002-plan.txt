## Plan

### Real problem (confirmed)

`dedupe.py` has two ranking functions that disagree:

- `pick_canonical` (write path) filters to playable files first, then takes the largest (`dedupe.py:3-7`).
- `suggest_keep` (display path) takes the largest **without** any playability check (`dedupe.py:10-14`).

Verified against `mirror_groups.json`: for `group_42`, `suggest_keep` returns `scenes:100` (playable=false, 5.2 GB) while `pick_canonical` correctly returns `scenes:101` (playable=true, 1.8 GB). The review page therefore tells the user to keep a proven-dead file and delete the playable one — the exact duplicate-removal error the task is about.

### Concrete fix (edit `dedupe.py` only)

Make the display ranking honor playability so it matches the canonical logic:

Replace the `suggest_keep` body so it filters playable candidates first, then breaks ties by size — i.e. `suggest_keep` should mirror `pick_canonical`. Cleanest change is to have `suggest_keep` reuse the shared logic:

```
def suggest_keep(candidates):
    """DISPLAY-ONLY ranking shown on the review page."""
    return pick_canonical(candidates)
```

(Or inline the equivalent two-line filter+max, but delegating to `pick_canonical` avoids the two functions drifting apart again.)
