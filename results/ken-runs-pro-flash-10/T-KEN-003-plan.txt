## Findings

`performers.json` is a single-line JSON object `{"performers": [...]}` with **2700** records, each `{id, name, image, stashdb_id}`.

The bug is a **wrong host IP in exactly 179 records**:

| group | ids | image host | count |
|-------|-----|------------|-------|
| broken | 0–178 | `http://198.51.100.64:9999/performer/{id}/image` | **179** |
| working | 179–2699 | `http://198.51.100.69:9999/performer/{id}/image` | 2521 |

- The `.64` host is a stale/broken Stash server; `.69` is the correct one used by the other 2521 records. The path/port are otherwise identical.
- `stashdb_id` is non-null only for ids 0–39 (`"stashdb-0"`…`"stashdb-39"`) and `null` for the other 2660, so `stashdb_mock.get_fallback_image()` (returns `https://stashdb.org/images/{id}.jpg`, else `None`) can only cover 40 of the 179 and would point at an unrelated external source. It is **not** the right fix here — the correct fix is the host correction.

## Plan for WORK model

**Root cause:** 179 performer records (ids 0–178) have `image` URLs pointing at host `198.51.100.64` instead of `198.51.100.69`, producing 179 broken grid thumbnails.

**Fix (edit only `performers.json`):**
1. Load `performers.json`, iterate `data["performers"]`.
