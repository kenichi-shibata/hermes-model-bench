The `.pyc` matches the current source, so the bug is in the code itself. Analysis:

**Root cause:** `build_card` unconditionally overwrites `scene['name_en']` with the result of `romanize(...)`, and `romanize` silently returns `None` for any performer missing from its tiny hardcoded table. So any performer not in the dict gets `name_en` clobbered to `null` — even if the scene already had a translation. That's why cards keep showing up with missing translations.

**Fix:** only write `name_en` when a real translation exists, and warn (instead of silently nulling) when none is available.
