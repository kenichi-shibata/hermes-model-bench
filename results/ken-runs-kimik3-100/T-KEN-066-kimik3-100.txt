## Finding: Bot is a zombie — alive but disconnected

```json
{
  "process_alive": true,       // process hasn't crashed
  "gateway_connected": false,  // ...but gateway connection is dead

```

**Why it's not responding:** The bot process is still running, but its gateway (websocket) connection dropped **20 minutes ago** and it never re-established it. So it looks "up" from a process standpoint, but it can't receive or send anything — which is exactly why it's silent.

This rules out a crash. It's a hung/stale connection state, and the bot's own reconnect logic has clearly failed (or doesn't exist), since a healthy client would have reconnected within seconds to a couple of minutes.

## Recommended action

1. **Restart the bot process** — this is the fix. A restart forces a fresh gateway handshake and will restore responsiveness immediately. Simply waiting won't help; it's already proven it can't recover on its own.
2. **After it's back up, harden it** so this doesn't recur:
   - Add/fix **auto-reconnect with backoff** on gateway disconnect.
   - Add a **heartbeat/zombie-session watchdog**: if `gateway_connected == false` for more than ~2–5 minutes, self-terminate and let the supervisor (systemd/pm2/docker) restart it.
   - Alert on disconnect duration, not just process liveness — a liveness check alone would have said "healthy" here.

Note: there's no live bot process inside this sandbox environment itself — the status file is the authoritative state, so the restart needs to happen wherever the bot is actually hosted.
