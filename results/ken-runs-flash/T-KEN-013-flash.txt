Review of the 4-file PR:

**`file2_pagination.py` — bug (the real issue).** `offset = page * limit` on line 4 is off-by-one. With `page=1, limit=10` it returns `items[10:20]`, skipping the first page entirely. Fix: `offset = (page - 1) * limit`.

**`file4_tests.py` — coverage gap.** `test_serialize` is a stub and there's no test for `paginate`, which is exactly where the bug is. The fix needs a test asserting `paginate([1,2,3], 1, 2) == [1,2]` and `page=2` returns `[3]`.

**`file1_models.py` / `file3_serializer.py` — fine.** Simple, consistent with each other.

One design note: after the fix, `page=0` would produce a negative offset (`-limit`), so consider validating `page >= 1` in `paginate` rather than relying on callers.

Net: merge-blocking only because of the off-by-one; the stub test and missing pagination test should be addressed in the same PR.
