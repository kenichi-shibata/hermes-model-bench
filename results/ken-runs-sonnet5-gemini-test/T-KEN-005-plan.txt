## What's actually wrong

This is a small, self-contained repro (just `api.py` + `scenes.json`). There is exactly one bug, and it's already called out in the code's own comments — I verified it's real by executing both section builders:

```
trending: performers -> [{'name_jp': '彩月七緒', 'name_en': 'Nanao Ayatsuki'}]   ✅ translated
resume:   performers -> [{'name_jp': '彩月七緒', 'name_en': None}]               ❌ not translated
```

**Root cause** (`api.py`):
- `_scene_out(scene, translate=False)` (line 3) only calls `romanize()` to fill `name_en` when `translate=True` is passed.
- `_home_trending()` (line 19) correctly calls `_scene_out(s, translate=True)` — this is the homepage "trending" row, and it works.
- `_hydrate_code()` (lines 22-24) is the builder for the **resume/continue-watching** row, and it calls `_scene_out(scene)` **without** `translate=True`. Since the default is `False`, `name_en` stays `None` for every performer whose `name_en` is missing in the source data.

That's exactly the user's complaint:
- "no translation cards on homepage" → the resume/continue-watching cards, because their `name_en` comes back `null` from the API, so the frontend has nothing to render as the blue romanized line under the Japanese name.
- "names of performer cards most of them are not translated" → same root cause: `name_en` is only populated when `translate=True` reaches `_scene_out`, and one of the two section builders never sets that flag.

There is no frontend code in this sandbox to touch (no templates/JS present) — the fix is entirely in the data being returned by the API layer. `scenes.json` is fine as-is (its `name_en: null` values are intentional fixture data meant to exercise the romanization path); it does not need editing.

## Exact fix for the WORK model

File: `api.py`

Change line 24 from:
```python
    return _scene_out(scene)  # missing translate=True
```
to:
```python
    return _scene_out(scene, translate=True)
```

Also clean up the now-stale comments/docstrings that describe the bug as still-present, since they'll be misleading once fixed:
- Lines 5-8 (docstring on `_scene_out`): remove/rewrite the "BUG: ... never passes translate=True ..." note.
- Line 23 (docstring on `_hydrate_code`): remove "BUG: forgot translate=True."
