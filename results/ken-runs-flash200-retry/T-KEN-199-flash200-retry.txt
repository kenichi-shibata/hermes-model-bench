Built from scratch: `stale_watcher.py` + `test_stale_watcher.py` (stdlib-only, all 11 tests pass).

What it does:
- **Staleness rule**: any wanted item in an active status (`pending`/`waiting`/`in_progress`) whose `updated_at` (falls back to `created_at`) is >48h old is flagged. Terminal statuses are never stale.
- **Auto-flag**: sets `flagged=1` + `flagged_at`, preserving the original flag time on re-scans (idempotent). Also auto-clears the flag when an item starts moving again.
- **Watcher**: `watch()` polls on an interval; CLI has `--once`, `--dry-run`, `--interval`, `--db`. Uses the same `db.query('SELECT * FROM wanted')` convention as `existing_related_code.py`.
- Testable via injected `now`; includes `CREATE TABLE IF NOT EXISTS wanted` so the schema self-provisions.

Run: `python3 stale_watcher.py --once` (single pass) or `python3 stale_watcher.py --interval 300` (continual watch).

Two assumptions worth confirming: the `wanted` table schema (added `flagged`/`flagged_at`/timestamps since none existed), and the list of "active" statuses.
