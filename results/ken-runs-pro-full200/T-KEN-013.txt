## Review

**Critical bug** — `file2_pagination.py:4`

```python
offset = page * limit  # should be (page - 1) * limit
return items[offset:offset + limit]
```

Off-by-one: for `page=1`, `offset = limit`, so the first `limit` items are skipped and page 1 returns items `[limit:2*limit]`. First page is empty when `items` has ≤ `limit` items. Fix:

```python
offset = (page - 1) * limit
return items[offset:offset + limit]
```

**Other observations (minor / non-blocking):**
- `file1_models.py` and `file3_serializer.py` look correct.
- `file4_tests.py` only stubs `test_serialize` (`pass`); there's no test covering `paginate`, which is exactly why this bug slipped through. Add a test asserting `paginate(items, 1, 2) == items[0:2]`.
- `paginate` doesn't guard `page < 1` or `limit <= 0`; with `page=0` it returns `items[:limit]` (silently treats 0 as page 1), and `limit=0` returns an empty list — worth validating or documenting.
