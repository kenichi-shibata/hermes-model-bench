No — it's not implementing Elo. The code just does a fixed ±32 point swap regardless of rating difference (`elo_engine.py:2-3`), so ratings can never reflect how expected a win was.

What it currently produces vs. real Elo:

- Current: after the two matches → `a=1564, b=1468, c=1468`
- Real Elo (K=32) → `a≈1531, b≈1484, c≈1485`, because `a` was expected to beat `c` after already beating `b`.

The core bug: no expected-score calculation. A proper update looks like:

```python
def update(winner, loser, ratings, K=32):
    rw = ratings.get(winner, 1500)
    rl = ratings.get(loser, 1500)
    exp = 1 / (1 + 10 ** ((rl - rw) / 400))
    ratings[winner] = rw + K * (1 - exp)
    ratings[loser] = rl - K * (1 - exp)
    return ratings
```

With this, an underdog win moves points more than a favorite win, and equal ratings yield the same ±16 (K/2) split.
