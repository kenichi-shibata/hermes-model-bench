N+1 query problem. The API makes **500 DB queries** at ~8ms each (≈4000ms), which dominates the 4500ms total. Instead of one batched query, it's issuing a separate query per item (e.g., in a loop), so latency scales linearly with count. Fix: batch the lookup into a single `WHERE id IN (...)` query (or join), cutting it from ~4.5s to ~10ms.
