# PLAN REPORT — T-KEN-010

## Diagnosis: yes, there is a real bug (but it's not "recursive follow")

**What's actually happening:** In `bot.py`, the function `track_studio_or_performer()` bundles two actions that should be separate:

```python
def track_studio_or_performer(entity_id, entity_type):
    db.add_track(entity_id, entity_type)
    db.follow_discord(entity_id, entity_type)  # BUG: shouldn't be here
```

Every time you (or anyone) pressed **track** on a studio/performer, the bot *also* silently fired a **Discord follow** for that entity. That's why you see follows you never made — no recursion involved, just one stray `follow_discord()` call inside the track handler. The docstring in the file even documents this as a known bug with the intended fix.

**Evidence in `follow_log.json` (812 lines, 162 entries):**
- **142 illegitimate follows** (`"legit": false`, `"source": "track_button_bug"`): `perf_0`…`perf_139` (140 entries) **plus `codey_steele` and `cherry_kiss`** — the two you asked about. Confirmed: you never followed them; the bug did.
- **20 legitimate follows** (`"legit": true`, `"source": "manual_follow"`): `legit_perf_0`…`legit_perf_19`. These must be preserved.
