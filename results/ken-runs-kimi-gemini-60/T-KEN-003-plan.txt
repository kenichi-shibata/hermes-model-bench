## Diagnosis — the real problem

`performers.json` holds 2700 performer records (`{"performers": [...]}`, single-line JSON, ids 0–2699, keys: `id`, `name`, `image`, `stashdb_id`). Every image URL is well-formed, but they point at two different hosts:

| Host | Records | Performer ids | Status |
|---|---|---|---|
| `http://198.51.100.64:9999/performer/{id}/image` | **179** | 0–178 (contiguous) | **dead host → broken grid images** |
| `http://198.51.100.69:9999/performer/{id}/image` | 2521 | 179–2699 | working |

The "like 179 broken" is exactly this first group. The path scheme (`/performer/{id}/image`, path id == performer id) is identical on both hosts, so the live server can serve the same paths.

**Critical trap:** the provided `stashdb_mock.get_fallback_image()` only covers **40 of the 179** broken records:
- ids **0–39** have `stashdb_id: "stashdb-{id}"` → fallback yields `https://stashdb.org/images/stashdb-{id}.jpg`
- ids **40–178** (139 records) have `stashdb_id: null` → fallback returns `None`

A naive "use the mock for everything" fix would set 139 images to `null`, making things worse. The data is deliberately split: the correct fix is a hybrid.
